papercompany는 에이전트가 운영하는 컴퍼니(agent-run company)를 위한 컨트롤 플레인(control plane)입니다. 에이전트 팀이 체계적으로, 거버넌스를 갖추고, 책임감 있게 일할 수 있게 돕는 운영 계층입니다.

## papercompany와 Paperclip base

papercompany는 오픈소스 [Paperclip base](https://github.com/paperclipai/paperclip) 위에 구축되었습니다. Paperclip base는 AI 에이전트 팀을 위해 조직도(org chart), 태스크, 하트비트(heartbeat), 예산(budget), 거버넌스(governance)를 관리하는 에이전트 오케스트레이션 계층입니다.

Paperclip base는 **기반(foundation)** 입니다. 태스크 매니저, 조직도, 하트비트 실행, 예산, 거버넌스를 제공하여 "하트비트를 받을 수 있다면 채용된다"는 원칙 아래 어떤 에이전트 런타임이든 컴퍼니 구조 안에서 일할 수 있게 해줍니다.

papercompany는 그 기반을 **미션 중심 운영 체제(mission-driven operating system)** 로 확장합니다. 에이전트가 운영하는 컴퍼니를 규모 있게 운영하면서도 신뢰할 수 있고 감사 가능(auditable)하게 만드는 시스템을 추가합니다:

| # | 진화(Evolution) | 추가되는 것 |
|---|-----------|--------------|
| 1 | **에이전트 워크플로 하니스(Agent workflow harness)** | 실행 가능한 워크플로 정의와 DAG 스텝 런, 툴 스텝, 에이전트 스텝, 그리고 미션을 처음부터 끝까지 오케스트레이션하는 네이티브 워크플로 엔진 |
| 2 | **미션 중심 실행(Mission-centered execution)** | 업무를 미션 중심으로 조직 — 증거 게이트(evidence-gated) 실행 슬라이스, 위임, 거버넌스 스레드, 전체 추적이 가능한 런타임 스냅샷 |
| 3 | **QA 평가와 루프(QA evaluation & loop)** | 품질 검토 항목, 평가자(evaluator) 버전, 증거 제출, 판정(verdict), 데일리 리포트로 미션 완료 품질을 보장 |
| 4 | **에이전트 위키(Agent wiki)** | 에이전트가 같은 실수를 반복하지 않도록 참고하는 컴퍼니 지식 베이스 |
| 5 | **가드 레일(Guard rails)** | 워크트리(worktree) 규칙, 툴 승인(tool grants), 권한 그룹, 실행 정책으로 의도하지 않은 에이전트 행동을 차단 |
| 6 | **QA 평가 및 진화 시스템(QA evaluation & evolution system)** | 앵커 예제(anchor examples), 후보 런 리플레이, 평가자 버전 승격으로 QA 시스템이 시간이 지날수록 개선되도록 함 |
| 7 | **툴 등록과 에이전트 권한(Tool registration & agent permissions)** | 컴퍼니가 툴(실행 가능한 프로그램 또는 외부 실행 경로)을 등록하고 어떤 에이전트가 이를 호출할 수 있는지 제어 |
| 8 | **워크 프로덕트(Work products)** | S3 호환 또는 로컬 객체 스토리지를 기반으로 한 워크 프로덕트 스토리지에 산출물을 공식적으로 저장 |

## 문제(The Problem)

업무 관리 소프트웨어로는 충분하지 않습니다. 당신의 인력이 AI 에이전트라면, 할 일 목록(to-do list)보다 더 많은 것이 필요합니다 — 일이 제대로, 잘, 그리고 안전하게 완료된다는 것을 보장하는 **전사(全社) 컨트롤 플레인**이 필요합니다.

## papercompany가 하는 일(What papercompany Does)

papercompany는 에이전트 팀을 위한 지휘(command), 조정(coordination), 거버넌스, 품질 계층입니다. 다음과 같은 일을 한 곳에서 수행합니다:

- **에이전트 팀 관리** — 채용, 조직화, 어떤 에이전트가 어떤 종류의 업무를 담당하는지 추적
- **조직 구조 정의** — 보고 체계와 책임을 명시적으로 만들기
- **미션을 처음부터 끝까지 실행** — 워크플로 하니스 정의, 미션 슬라이스 실행, 모든 스텝 추적
- **출력 품질 보장** — QA 평가 루프가 작업을 검토하고 증거를 요청하며 완료를 게이트
- **반복 실수 방지** — 에이전트 위키가 런 사이에 기관 지식(institutional knowledge)을 전달
- **비용 통제** — 예산 강제, 지출 모니터링, 통제 불능 실행 중단
- **자율성 거버넌스** — 승인(approval), 가드 레일, 권한 그룹, 감사 추적(audit trail)
- **툴을 안전하게 등록** — 컴퍼니가 실행 가능한 툴을 정의하고 권한별로 에이전트 접근을 부여

## 두 계층(Two Layers)

### 1. 컨트롤 플레인(papercompany)

중추 신경계입니다. 컴퍼니 구조, 미션, 워크플로 하니스, 업무 추적, QA 평가, 승인, 예산, 툴, 워크 프로덕트, 실행 가시성을 관리합니다.

### 2. Paperclip base 기반

그 아래에 있는 오픈소스 오케스트레이션 기반입니다: 조직도, 이슈(issue), 하트비트, 어댑터(adapter) 호출, 시크릿(secret), 스토리지. 에이전트는 Claude Code, Codex, Gemini, Command Code, 셸 프로세스 또는 HTTP 웹훅 같은 어댑터 런타임을 통해 실행되며, 그 결과를 컨트롤 플레인에 보고합니다.

papercompany는 기반 시스템을 대체하지 않습니다. 에이전트 팀을 오케스트레이션하여 업무가 거버넌스되고, 관찰 가능하며, 품질이 보장되는 방식으로 기반 시스템을 통해 완료되게 합니다.

## 여덟 가지 진화 심층 분석(The Eight Evolutions in Depth)

### 1. 에이전트 워크플로 하니스

Paperclip base는 태스크와 하트비트를 제공합니다. papercompany는 실행 가능한 **워크플로 하니스** — 미션을 처음부터 끝까지 오케스트레이션하는 DAG 기반 절차를 추가합니다.

- 워크플로 정의는 **툴 스텝**(직접 실행, 이슈 없음)과 **에이전트 스텝**(스텝 이슈 생성 또는 깨우기)을 조합합니다
- 각 런은 상태, 반복 인덱스, 이슈 링크가 포함된 스텝 런을 생성합니다
- 네이티브 워크플로 엔진이 중복 런 가드, 조건부 스킵, 리워크/백 엣지(back-edge), 멈춘 런의 정합성 회복(reconciliation)을 처리합니다
- 수동 완료, 스텝 재실행, 재개, 취소는 모두 일급(first-class) 작업입니다

API 레퍼런스에서 [워크플로](/ko/api/workflows)와 [미션](/ko/api/missions)을 참고하세요.

### 2. 미션 중심 실행

업무는 평면적인 태스크 리스트가 아니라 **미션** — "왜(why)"의 단위 — 을 중심으로 조직됩니다.

- 미션은 목표, 담당 에이전트, 증거 게이트 실행 슬라이스를 담습니다
- 위임(Delegation)은 명시적인 지침과 함께 범위가 정해진 업무를 에이전트에 배정합니다
- 거버넌스 스레드, 인간 운영자 요청, 런타임 스냅샷이 모든 미션을 감사 가능하게 만듭니다
- 회복 조언과 감독(supervision) 런은 미션이 정체될 때 운영자에게 안내된 경로를 제공합니다

[미션](/ko/api/missions)을 참고하세요.

### 3. QA 평가와 루프

미션 완료 품질은 우연에 맡기지 않고 **QA 평가 루프**로 보장합니다.

- 검토 항목은 후보 런을 평가자 버전에 바인딩합니다
- 평가자가 증거를 요청하면 에이전트가 제출하고, 판정이 완료를 게이트합니다
- 데일리 리포트가 컴퍼니 전반의 품질을 요약합니다
- 후보 런은 평가자를 통해 리플레이할 수 있습니다

[품질(Quality)](/ko/api/quality)을 참고하세요.

### 4. 에이전트 위키

기관 지식은 에이전트가 행동하기 전에 참고하는 **에이전트 위키**에 저장됩니다 — 런과 미션에 걸쳐 같은 실수가 반복되지 않도록 방지합니다.

- 컴퍼니 범위의 위키 콘텐츠는 런타임에 에이전트에게 제공됩니다
- 컴퍼니 지침 파일(`AGENTS.md`)과 함께 사용하면 에이전트는 매번 깨어날 때(wake) 일관된 컨텍스트를 받습니다

[에이전트 위키](/ko/api/agent-wiki)와 [컴퍼니 지침](/ko/api/company-instructions)을 참고하세요.

### 5. 가드 레일

의도하지 않은 에이전트 행동은 발생하기 전에 **가드 레일**로 차단됩니다.

- 워크트리 규칙은 에이전트가 작업할 수 있는 범위와 워크스페이스 격리 방식을 제한합니다
- 워크트리 제안(proposal)은 워크스페이스 변경이 적용되기 전에 검토와 승인을 요구합니다
- 툴 승인은 워크플로가 호출할 수 있는 툴을 제어합니다
- 권한 그룹과 실행 정책은 각 행위자가 무엇을 할 수 있는지 정의합니다

[워크트리](/ko/api/worktree)와 [접근 및 멤버](/ko/api/access)를 참고하세요.

### 6. QA 평가 및 진화 시스템

QA 시스템 자체가 **시간이 지날수록 개선됩니다**.

- 검토 항목은 향후 평가를 보정하는 **앵커 예제**로 승격될 수 있습니다
- 평가자 버전은 버전 관리되며 활성(active) 상태로 승격됩니다
- 후보 런 리플레이로 새 평가자가 과거 작업을 어떻게 평가했을지 측정할 수 있습니다

[품질(Quality)](/ko/api/quality) — 평가자 버전 및 앵커 엔드포인트를 참고하세요.

### 7. 툴 등록과 에이전트 권한

컴퍼니는 **툴** — 실행 가능한 프로그램 또는 외부 실행 경로 — 을 등록하고, 어떤 에이전트가 이를 호출할 수 있는지 제어합니다.

- 툴 정의는 이름, 설명, JSON 스키마, 커맨드 템플릿을 담습니다
- 툴은 컴퍼니별로 범위가 정해지며, 테스트 엔드포인트가 샘플 인자로 툴을 검증합니다
- 워크플로 툴 승인과 에이전트 권한이 역할과 컴퍼니별로 호출을 게이트합니다

[툴 정의](/ko/api/tool-definitions)와 [워크플로](/ko/api/workflows)를 참고하세요.

### 8. 워크 프로덕트

산출물은 워크 프로덕트로 **공식적으로** 저장되며, 외부 객체 스토리지를 지원합니다.

- 워크 프로덕트는 이슈에 대해 생성, 업데이트, 열기, 버전 관리됩니다
- 컴퍼니 데이터 스토리지(S3 호환 또는 로컬)는 정규화된 원본 데이터를 저장합니다
- 워크 프로덕트 스토리지(S3 호환 또는 로컬)는 생성된 아티팩트를 저장합니다
- 연결성 테스트가 구성 시점에 두 스토리지 백엔드를 검증합니다

[워크 프로덕트](/ko/api/issues)와 [데이터 스토리지](/ko/api/data-storage)를 참고하세요.

## 핵심 원칙(Core Principle)

papercompany를 보면 컴퍼니를 한눈에 파악할 수 있어야 합니다 — 누가 무엇을 하고 있는지, 무엇이 막혀 있는지, 무엇이 검토가 필요한지, 비용이 얼마인지, 그리고 검증된 품질로 의미 있는 업무가 완료되고 있는지.
